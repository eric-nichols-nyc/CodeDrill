# Answer Evaluation System

## Purpose

The Answer Evaluation System analyzes a candidate's answer and determines whether sufficient evidence was provided to demonstrate the skills, behaviors, and expectations required for the role.

The system evaluates a single answer at a time.

The system does not generate interview questions.

The system does not generate final interview reports.

The system focuses on evidence collection and candidate assessment.

---

# Inputs

## Question

The interview question being answered.

Example:

```txt
How would you share authentication across independently deployed micro frontends?
```

---

## Expected Signals

Generated by the Interview Generator.

These represent the evidence a strong answer should contain.

Example:

```json
[
  "shared authentication strategy",
  "ownership boundaries",
  "token management",
  "team independence",
  "deployment considerations"
]
```

---

## Candidate Answer

Transcript generated from voice or text input.

Example:

```txt
I would probably use React Context to store the current user and share it across the applications.
```

---

# Responsibilities

## 1. Evaluate Evidence

Determine whether the candidate demonstrated the expected concepts.

The goal is not to determine whether the answer is technically correct.

The goal is to determine whether the answer provides evidence that the candidate can perform at the required level.

---

## 2. Identify Strengths

Determine which expected signals were demonstrated.

Example:

```json
[
  "Recognized need for shared authentication state",
  "Understood centralized user management"
]
```

---

## 3. Identify Weaknesses

Determine what was missing.

Example:

```json
[
  "Did not discuss ownership boundaries",
  "Did not discuss deployment independence",
  "Did not discuss token refresh strategy"
]
```

---

## 4. Calculate Confidence

Determine how much confidence the answer provides that the candidate satisfies the role requirements.

Example:

```json
{
  "confidenceLevel": "Low",
  "reason": "Answer demonstrated basic implementation knowledge but did not show evidence of senior architectural thinking."
}
```

---

## 5. Generate Coaching Feedback

Provide actionable guidance.

Example:

```txt
A stronger answer would explain where authentication should live, how independently deployed applications consume authentication data, and how teams remain decoupled while sharing security contracts.
```

---

## 6. Recommend Follow-Up Topics

Suggest areas for additional practice.

Example:

```json
[
  "Authentication architecture",
  "Micro frontend boundaries",
  "Token lifecycle management"
]
```

---

# Outputs

## Evaluation Result

Example:

```json
{
  "score": 6,

  "strengths": [
    "Recognized need for shared authentication state"
  ],

  "weaknesses": [
    "Did not discuss ownership boundaries",
    "Did not discuss deployment strategy"
  ],

  "missingSignals": [
    "team independence",
    "deployment considerations"
  ],

  "confidenceLevel": "Low",

  "suggestedAnswer": "A stronger answer would explain centralized authentication, ownership boundaries, deployment independence, and shared contracts.",

  "recommendedTopics": [
    "Micro Frontends",
    "Authentication",
    "Architecture"
  ]
}
```

---

# Evaluation Criteria

The system should evaluate:

## Technical Accuracy

```txt
Was the answer technically sound?
```

---

## Completeness

```txt
Did the answer cover the expected signals?
```

---

## Depth

```txt
Did the answer demonstrate senior-level understanding?
```

---

## Communication

```txt
Was the answer clear and structured?
```

---

## Evidence Of Role Fit

```txt
Did the answer increase confidence that the candidate can perform this role?
```

# How Other Systems Use This

Displays:

* Score
* Strengths
* Weaknesses
* Suggested answer
* Recommended topics

---

## Reporting System

Aggregates evaluation results across the entire interview.

Uses:

* Scores
* Confidence levels
* Weakness patterns
* Strength patterns

to generate the final interview report.

---

# MVP Scope

The MVP should:

1. Evaluate one answer at a time
2. Compare answer against expected signals
3. Identify strengths
4. Identify weaknesses
5. Identify missing signals
6. Generate confidence assessment
7. Generate coaching feedback
8. Recommend follow-up topics

The MVP should not:

* Generate interview questions
* Generate final reports
* Track interview progress
* Create study plans
* Compare multiple interviews

Those responsibilities belong to other systems.

---

# Guiding Principle

The Answer Evaluation System is not trying to determine whether the answer is correct.

The Answer Evaluation System is trying to determine:

"Did this answer provide sufficient evidence that the candidate satisfies the expectations of the role?"
