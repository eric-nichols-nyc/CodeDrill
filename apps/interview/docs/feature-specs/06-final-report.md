# Final Report System

## Purpose

The Final Report System analyzes the results of the entire interview and identifies patterns, strengths, weaknesses, risk areas, and recommended next steps.

The Final Report System does not evaluate individual answers.

The Final Report System looks across all answers and determines what was learned about the candidate.

Its purpose is to answer:

> What patterns emerged during the interview, and what should the candidate do next?

---

# Inputs

## Interview Session

Contains:

* Interview metadata
* Questions
* Categories
* Duration
* Completion status

---

## Evaluation Results

Generated by the Answer Evaluation System.

Contains:

* Scores
* Strengths
* Weaknesses
* Missing signals
* Confidence assessments
* Recommended topics

for every question in the interview.

---

# Responsibilities

## 1. Identify Strength Patterns

Determine areas where the candidate consistently performed well.

Example:

```txt
Strong React knowledge

Strong Design System experience

Strong Accessibility knowledge

Strong stakeholder communication
```

---

## 2. Identify Weakness Patterns

Determine areas where the candidate repeatedly struggled.

Example:

```txt
Architecture communication

System design explanations

Observability

Micro frontend deployment strategy
```

---

## 3. Identify Risk Areas

Determine concerns a hiring manager might have.

Example:

```txt
Can explain implementation details

Struggles to explain architectural tradeoffs

Limited evidence of technical leadership

Limited evidence of system ownership
```

---

## 4. Measure Role Readiness

Estimate how prepared the candidate is for the target role.

Example:

```txt
Role:
Senior Frontend Engineer

Readiness:
75%

Confidence:
Medium
```

---

## 5. Generate Coaching Recommendations

Provide specific next steps.

Example:

```txt
Practice architecture discussions.

Focus on deployment boundaries in micro frontend systems.

Prepare examples of mentoring and technical leadership.
```

---

## 6. Generate Study Recommendations

Recommend topics for future practice.

Example:

```txt
Micro Frontends

Observability

Frontend Architecture

System Design

Technical Leadership
```

# How Other Systems Use This

The Final Report System is the last step in the interview pipeline.

```txt
Profile System
↓
Job Analysis System
↓
Interview Generator
↓
Question Player
↓
Answer Evaluation System
↓
Final Report System
```

No downstream systems depend on the Final Report.

It is the final output presented to the candidate.

---

# MVP Scope

The MVP should:

1. Aggregate evaluation results
2. Identify strength patterns
3. Identify weakness patterns
4. Identify risk areas
5. Estimate role readiness
6. Generate coaching recommendations
7. Generate study recommendations
8. Produce a final interview summary

The MVP should not:

* Rewrite resumes
* Apply for jobs
* Generate learning plans
* Track long-term progress
* Compare multiple interview sessions

Those features belong to future versions.

---

# Guiding Principle

The Final Report System is not trying to score the interview.

The Final Report System is trying to answer:

"What did we learn about this candidate, and what should they do next to improve their chances of getting hired?"
