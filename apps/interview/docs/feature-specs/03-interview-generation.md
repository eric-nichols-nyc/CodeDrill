# Interview Generator System

## Purpose

The Interview Generator creates an interview blueprint based on:

* Candidate Profile
* Job Analysis

Its purpose is to determine what evidence must be collected to evaluate whether the candidate is a strong fit for the role.

The Interview Generator does not evaluate answers.

The Interview Generator does not score candidates.

The Interview Generator creates the interview plan.

---

# Inputs

## Candidate Profile

Generated by the Profile System.

Provides:

* Candidate summary
* Skills
* Projects
* Claims to verify
* Strength areas
* Gap areas

---

## Job Analysis

Generated by the Job Analysis System.

Provides:

* Required skills
* Nice-to-have skills
* Seniority level
* Interview categories
* Hidden expectations
* What the candidate must prove

---

# Outputs

## Interview Blueprint

A structured interview plan.

Example:

```json
{
  "interviewTitle": "Senior Frontend Engineer Interview",
  "estimatedDuration": 30,
  "questionCount": 10,
  "categories": [
    "React Architecture",
    "Micro Frontends",
    "Design Systems",
    "Leadership",
    "Testing"
  ]
}
```

---

## Interview Categories

Determine which areas should be tested.

Example:

```json
[
  "Resume Deep Dive",
  "React Architecture",
  "Micro Frontends",
  "Design Systems",
  "Testing",
  "Leadership"
]
```

---

## Question Order

Questions should progress from easier to more difficult.

Example:

```txt
1. Resume Deep Dive
2. React Fundamentals
3. Architecture
4. System Design
5. Leadership
```

---

## Generated Questions

Questions should be based on:

* Resume claims
* Required skills
* Hidden expectations
* Seniority level

Example:

```json
{
  "category": "Micro Frontends",
  "difficulty": "Senior",
  "question": "How would you share authentication across independently deployed micro frontends?"
}
```

---

## Expected Signals

Each question should define the evidence a strong answer would contain.

Example:

```json
[
  "shared authentication strategy",
  "ownership boundaries",
  "token management",
  "team independence",
  "deployment considerations"
]
```

---

## Follow-Up Opportunities

Potential areas to probe further.

Example:

```json
[
  "Ask about token refresh strategy",
  "Ask about security concerns",
  "Ask about deployment ownership"
]
```

# How Other Systems Use This

## Question Player

Receives:

* Questions
* Categories
* Difficulty
* Order

Displays questions one at a time.

---

## Evaluation System

Receives:

* Question
* Expected Signals
* Candidate Answer

Uses Expected Signals to determine whether the candidate provided sufficient evidence.

---

# MVP Scope

The MVP should:

1. Receive Candidate Profile
2. Receive Job Analysis
3. Generate interview blueprint
4. Generate categories
5. Generate 5–10 questions
6. Generate expected answer signals
7. Generate follow-up opportunities

The MVP should not:

* Evaluate answers
* Score candidates
* Produce interview reports
* Track progress

Those responsibilities belong to later systems.

---

# Guiding Principle

The Interview Generator is not trying to create questions.

The Interview Generator is trying to determine:

"What evidence do we need to collect to decide whether this candidate satisfies the expectations of this role?"
